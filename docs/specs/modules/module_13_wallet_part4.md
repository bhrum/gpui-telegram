## 2. Core Architectural Design & State Machines

### 2.1 Wallet Engine & Lifecycle State Machine (`wallet_engine.cpp:L42-L180`)

The TON Wallet Engine orchestrates network communication, keystore access, transaction serialization, and event notification across the desktop runtime.

```
                      +-------------------+
                      |   Uninitialized   |
                      +---------+---------+
                                | (init with config)
                                v
                      +-------------------+
                      |   Connecting      |
                      +---------+---------+
                                | (lite-server handshake)
                                v
                      +-------------------+
                      |      Ready        |<================+
                      +---------+---------+                 |
                                |                           |
             +------------------+------------------+        |
             |                                     |        |
             v                                     v        |
   +--------------------+               +--------------------+
   | Querying Account   |               | Preparing Transfer |
   +---------+----------+               +----------+---------+
             |                                     |
             | (state / seqno)                     | (BOC created)
             v                                     v
   +--------------------+               +--------------------+
   | Balance Updated    |               | Signing & Broadcast|
   +--------------------+               +----------+---------+
                                                   |
                                                   v
                                        +--------------------+
                                        | Transaction Sent   |
                                        +--------------------+
```

#### Key Architecture Parameters:
- `kMaxTrackedEarlyCancels = 64`: Upper bound of early canceled transaction hashes retained in memory to avoid redundant confirmation alerts.
- `kRoutedSendTimeout = 15,000ms`: Maximum time window allocated for Bag-of-Cells (BOC) external message routing via TON lite-servers before triggering network retry or failure state.

### 2.2 Key Custody, Argon2id & Hardware Protection (`wallet_key_protection.cpp:L75-L160`)

Telegram TON Wallet employs a multi-tiered cryptographic protection model:
1. **Local Vault Wrapping**:
   - The master 24-word seed phrase or private key is encrypted with AES-256-GCM.
   - The key wrapping key (KWK) is derived using Argon2id:
     $$\text{KWK} = \text{Argon2id}(\text{passcode}, \text{salt}_{32}, \text{iterations}=3, \text{memory}=64\text{MB}, \text{parallelism}=4)$$
   - When biometrics (Touch ID / Face ID / Windows Hello) are enabled, the KWK is protected by the OS secure enclave / keychain.
2. **Cleanse Zeroization Guard**:
   - Sensitive byte buffers (raw mnemonic words, derived private keys, intermediate PBKDF2/Argon2 outputs) are wrapped in zeroizing containers (`gsl::finally([&] { sodium_memzero(...); })`) ensuring no plain secrets linger in heap memory.
3. **Custody Record Format (`wallet_custody.cpp:L17-L25`)**:
   - Stored under key `custody/records` with version header `quint32(4)`.
   - Bit flags: `kActiveFlag = (1 << 0)` indicates an active signing key. When a key is rotated, the old record has `kActiveFlag` cleared and a `PendingRotation` record is scheduled.

### 2.3 Shamir Seed Phrase Secret Sharing (`wallet_phrase_shares.cpp:L28-L85`)

To safeguard the 24-word recovery phrase without cloud custody, the wallet provides a K-of-N threshold secret sharing scheme over Galois Field $GF(2^8)$:
- Secret polynomial: $P(x) = S + a_1 x + a_2 x^2 + \dots + a_{k-1} x^{k-1} \pmod{2^8}$
- Each share contains an index $x_i$ and value $y_i = P(x_i)$.
- Secret recovery via Lagrange interpolation:
  $$S = \sum_{j=1}^k y_j \prod_{m \ne j} \frac{x_m}{x_m - x_j}$$
- Each share is encrypted with a recipient peer's temporary Diffie-Hellman public key (`TemporaryKeyPair`).
### 2.4 Diamond Particle Flight Physics (`wallet_diamond_flight.cpp:L21-L70`)

When a TON or collectible gift transaction is confirmed, the desktop UI renders airborne particle gems traversing a parabolic bezier flight curve:
- Constants:
  - `kFlightRise = 0.06`
  - `kApexLatest = 0.4`
- Trajectory Formula:
  $$x(t) = (1-t)^2 x_0 + 2(1-t)t x_c + t^2 x_1$$
  $$y(t) = (1-t)^2 y_0 + 2(1-t)t y_c + t^2 y_1 - 4 \cdot H \cdot t (1 - t)$$
- Particle Alpha and Scale:
  $$\alpha(t) = \begin{cases} t / 0.15 & t < 0.15 \\ 1.0 & 0.15 \le t \le 0.75 \\ (1 - t) / 0.25 & t > 0.75 \end{cases}$$
  $$\text{scale}(t) = 0.6 + 0.4 \sin(\pi t)$$

### 2.5 Real-Time Rates & Currency Formatting (`wallet_fiat.cpp:L28-L45`, `wallet_rates.cpp:L18-L35`)

The rates subsystem maintains periodic currency conversions:
- `kRefreshTimeout = 300,000ms` (5 minutes polling frequency).
- `kRetryTimeout = 30,000ms` (30 seconds backoff on network failure).
- Conversion equation:
  $$\text{FiatValue} = \left(\frac{\text{nanoTON}}{10^9}\right) \times \text{Rate}_{\text{TON}/\text{Fiat}}$$
- Precision scaling: `kTinyFiatScale = 15` decimal places for micro-conversions, `kGramDigits = 9` standard decimal representation for TON amounts.
