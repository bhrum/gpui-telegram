## 2. Core Architectural Design & State Machines

### 2.1 Checkout Process Lifecycle & State Machine (`payments_checkout_process.cpp:L37-L155`)

The checkout coordinator manages asynchronous payment transactions across panel-based flows, webviews, and non-panel Telegram Stars/Credits flows.

```
                  [ Checkout Start ]
                          |
             +------------+------------+
             |                         |
    [ Panel Flow ]            [ Non-Panel Flow ]
             |                         |
     (Form Details)            (Stars / Credits)
             v                         v
     [ SubmitState ]           [ Balance Check ]
     - None                            |
     - Validating                      v
     - Validated            (Insufficient -> Top-Up)
     - Finishing                       |
             |                         v
             +------------+------------+
                          |
                   [ Outcome Gate ]
                          |
      +---------+---------+---------+---------+
      |         |         |         |         |
    Paid     Pending  Cancelled   Failed     Free
```

#### Multi-Session Process Registry
Upstream desktop maintains a singleton process table per active session (`LookupSessionProcesses`):
1. **By Message ID (`byItem`)**: Invoices attached to chat messages (`FullMsgId { peer, msg_id }`).
2. **By Slug (`bySlug`)**: Invoice links (`t.me/$slug`).
3. **By Random ID (`byRandomId`)**: Premium gift codes, Telegram Stars top-ups, and Star Gifts.
4. **Payment Started Notifications (`paymentStartedByItem`, `paymentStartedBySlug`)**: Preserves invoice confirmation before panel tear-down.

### 2.2 Payment Form Details & Credential Architecture (`payments_form.h:L41-L121`, `payments_form.cpp:L200-L450`)

The form encapsulates all customer input, saved provider credentials, shipping calculations, and 2FA cloud password requirements:

1. **Form Details (`FormDetails`)**:
   - `formId`: 64-bit unique form identifier.
   - `url`: Bot payment webview URL or invoice link.
   - `nativeProvider`: Provider identifier string (e.g., `"stripe"`, `"smartglocal"`).
   - `nativeParamsJson`: Provider-specific configuration payload (publishable keys, URLs).
   - `canSaveCredentials`: Boolean flag allowing card token persistence.
   - `passwordMissing`: Boolean flag indicating user must setup Telegram 2FA cloud password before card saving.
   - `termsAccepted`: Terms of service acceptance confirmation.

2. **Credentials Storage Hierarchy**:
   - `SavedCredentials`: Saved card tokens stored on Telegram servers (`id`, `title`, masked number).
   - `NewCredentials`: Fresh tokenized payment data (`title`, `data`, `saveOnServer`).
   - `NativePaymentMethod`: Variant containing either `StripePaymentMethod` or `SmartGlocalPaymentMethod`.

3. **Invoice Types (`InvoiceId`)**:
   - `InvoiceMessage`: Chat message invoice.
   - `InvoiceSlug`: Web slug invoice link.
   - `InvoicePremiumGiftCode`: Telegram Premium gift code purchase.
   - `InvoiceCredits`: Telegram Stars top-up.
   - `InvoiceStarGift`: Limited or unique star gift dispatch.

### 2.3 Non-Panel Payment & Star Gifts (`payments_non_panel_process.cpp:L36-L120`)

Transactions paid via Telegram Stars (currency `"XTR"` / `Ui::kCreditsCurrency`) bypass the physical credit card panel:
- `IsCreditsInvoice(item)`: Inspects message invoice currency for `XTR` or service payment records.
- `ProcessCreditsPayment`: Checks star balance via `Settings::MaybeRequestBalanceIncrease`.
- Error Handling:
  - `STARGIFT_USAGE_LIMITED`: Gift is completely sold out. Displays `tr::lng_gift_sold_out_title`.
  - `STARGIFT_USER_USAGE_LIMITED`: Reached maximum purchase limit per user. Displays `tr::lng_gift_sent_finished`.
  - Small balance blocked/cancelled outcomes convert directly to `CheckoutResult::Failed` and `CheckoutResult::Cancelled`.

### 2.4 Paid Message Reactions & Star Donor Leaderboard (`payments_reaction_process.cpp:L43-L125`)

Paid reactions allow channel subscribers to react with Telegram Stars:
- **Default & Maximum Values**:
  - `kDefaultPerReaction = 50` stars per reaction tap.
  - `kMaxPerReactionFallback = 10'000` stars ceiling per reaction.
- **Anonymous Reactions**:
  - `LookupMyPaidAnonymous(item)`: Scans top paid reaction entries to check whether current user opted for anonymous sender identity.
- **Balance Gate**:
  - `TryAddingPaidReaction`: Checks sender's star balance. If insufficient, triggers `Settings::MaybeRequestBalanceIncrease` dialog before committing reaction animation.

### 2.5 Tokenization Clients: Stripe & SmartGlocal Protocols (`stripe_api_client.cpp`, `smartglocal_api_client.cpp`)

#### Stripe Tokenization Protocol
- **API Base URL**: `https://api.stripe.com/v1/tokens` (`APIURLBase = "api.stripe.com/v1"`, `TokenEndpoint = "tokens"`).
- **Protocol Versions**:
  - `Stripe-Version: 2015-10-12`
  - `SDKVersion: 9.1.0`
  - `X-Stripe-User-Agent: {"lang":"objective-c","bindings_version":"9.1.0"}`
  - `Authorization: Bearer <publishableKey>`
- **Form Encoded Fields**:
  - Root object: `card`
  - Keys: `card[number]`, `card[cvc]`, `card[name]`, `card[address_line1]`, `card[address_line2]`, `card[address_city]`, `card[address_state]`, `card[address_zip]`, `card[address_country]`, `card[exp_month]`, `card[exp_year]`, `card[currency]`.
- **Card Brand Detection**:
  - Visa, American Express, MasterCard, Discover, JCB, Diners Club, UnionPay, Unknown.

#### SmartGlocal Tokenization Protocol
- **Production Base**: `https://tgb.smart-glocal.com/cds/v1/tokenize/card`
- **Playground Base**: `https://tgb-playground.smart-glocal.com/cds/v1/tokenize/card`
- **URL Whitelist Validation**:
  - Scheme must be `https`.
  - Host must end with `.smart-glocal.com`.
  - Path must equal `/cds/v1/tokenize/card`.
  - No query string or URL fragments permitted.
- **Headers & Payload**:
  - Header: `X-PUBLIC-TOKEN: <publicToken>`
  - Body: JSON format `{"card": {"number": "...", "expiration_month": "MM", "expiration_year": "YY", "security_code": "CVC"}}`
- **Masked Card Last4 Extraction**:
  - Regular Expression: `[^\\d]\\d*(\\d{4})$` applied to `masked_card_number`.
