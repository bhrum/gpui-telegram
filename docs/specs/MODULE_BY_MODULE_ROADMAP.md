# Telegram 1:1 Parity Module-by-Module Roadmap

## Executive Summary & Mandate #15 Protocol

This roadmap defines the sequential, module-by-module execution plan for the full Telegram Desktop 1:1 reconstruction across all **28 subsystems**, **3,441 upstream source files**, and **1,897 target Rust/GPUI units** in strict adherence to **User Mandate #15**:

> **"可是源码还是得看了设计好，然后再去做，一步一步来，有清单，就是安排好计划，先把一个模块对照源码，阅读然后在实施，实施完后要发布测试版，验收，验收完再搞下一个，而不是一下子全搞好，一个模块一个模块的源码对照理解实现验收再到下一个模块，还是要有账本和理解落地"**

### Zero-Tolerance Boilerplate Rule
All batch-generated template stubs must be burned down and replaced module-by-module with authentic implementations. The 4 prohibited fake boilerplate patterns are:
- **Pattern A**: `pub label: String, pub value: i64` and `self.updated_at = chrono::Utc::now().timestamp(); true`
- **Pattern B**: `//! Autogenerated authentic GPUI Telegram view component` with `pub label: String, pub value: i64`
- **Pattern C**: `//! Materialized Rust GPUI Component` with `self.count = self.count.saturating_add(1);`
- **Pattern D**: `pub id: u64, pub tag: String, pub value: String`

### Strict 4-Step Module Closed Loop
Each module must complete all four steps before the orchestrator may advance to the next module:
1. **Step A — Deep C++ Source Reading & Module Design Doc (`源码对照阅读与理解落地`)**:
   Read real C++ files in `/Users/bhrum/.gemini/antigravity/scratch/tdesktop/Telegram/SourceFiles/<subsystem>/`. Author `docs/specs/modules/module_<nn>_<name>.md` detailing real structs, methods, state machines, and `.style` tokens.
2. **Step B — Genuine Rust + GPUI Implementation (`真实代码实现`)**:
   Replace all boilerplate stubs in that module with authentic Rust domain and GPUI view implementations faithful to upstream C++.
3. **Step C — Test Build Packaging (`编译发布测试版`)**:
   Build runnable binaries (`cargo build --bin gpui_telegram_desktop --bin gpui_telegram_server`), clean build garbage (`clean_build_garbage.py`), and run unit + integration tests.
4. **Step D — Module Acceptance Gate (`单模块独立验收`)**:
   Verify **0 boilerplate pattern files** exist in that module. Reviewer, Challenger, and Forensic Auditor verify genuine implementation before marking the module `ACCEPTED`.
